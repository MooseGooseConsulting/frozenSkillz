# ChatGPT Web Adapter

Use this proposal-first adapter for actual ChatGPT web history and Projects, not merely
ChatGPT conversations displayed in the Codex sidebar. Acquire the requested
surface through the browser or a fresh successful local export snapshot. Inventory
normal history, lazy-loaded history, archives when requested, and Projects. A
browser agent returns source IDs, Project IDs, detailed body summaries, unreadable
results, and evidence — never title-only recommendations. The coordinator performs
cross-cluster reconciliation.

## Read-Only Proposal Workflow

1. Inventory the requested surface and every existing Project.
2. Acquire and summarize every selected conversation body.
3. Build semantic clusters and supported relationships with the shared rules.
4. Produce the concise evidence worksheet.
5. Propose old/new titles, existing-Project moves, relationships, and separately
   proposed new Projects, Project merges, or Project reorganizations.
6. Grade body coverage, title specificity, cluster cohesion, emoji fit,
   relationship confidence, and collision risk; revise failed or weak proposals.
7. Wait for explicit approval. Never create a Project, merge/reorganize Projects,
   rename, move, archive, or otherwise mutate ChatGPT before approval.

Prefer existing Projects. New Projects or Project structural changes are a
separate recommendation requiring approval. Do not infer Codex completion state,
status emoji, or current-owner state for ChatGPT conversations.

## Approved Mutation and Verification

Apply only the approved title changes and moves in the browser. Re-open and read
back every changed conversation and confirm the exact title and Project membership.
Report exact applied, skipped, failed, and concurrently changed totals. A fresh
local snapshot may accelerate large read-only analysis, but ChatGPT remains the
source of truth; use live browser pages for mutation and verification.
